# 1.14.0 compatibility evidence and classification

Baseline: npm `@absmartly/javascript-sdk@1.13.4`, downloaded with `npm pack`.
There is no 1.13.4 git tag (tags stop at 1.11.2). Source commit
`47390aecde99b76adb610adb30fcdb13121c6459` produces byte-identical `.d.ts`
and CJS files, except the registry artifact also has an empty stale `lib/types.js`.
Unreleased main and preserved `origin/next/major` both initially point to
`311cfca6fbefafb23ea26684ec64a72d4509a8a8`; no preservation branch was recreated.
No tag or package is published by this PR.

## Measurements

- Released source suite on release: **263 passed / 29 suites**.
- Released suite on unreleased main: **234 passed, 29 failed / 29 suites**.
  Failures: GET headers, ruleOverride/sdKVersion exact payload assertions, and two
  custom-field logging contract assertions (the async assertion failures also time out).
- Released suite on candidate before normalization: **238 passed, 25 failed**;
  only documented new GET headers, versioned SDK agent and ruleOverride:false differ.
  Custom-field logging expectations pass after restoring the released contract.
- Candidate full build at first milestone: **547 passed / 38 suites**, formatting,
  ESLint, TypeScript, ES/CJS and both browser bundles pass.
- Cross-SDK snapshot `ada8952293a8d4ebf81f8de038f4e7a406d98870` (merged main):
  **277 tested and passed / 28 reviewed capability skips of 305**, no failures.
  Skips: 320/321 (the pinned snapshot still lists `xAgentHeader` as unsupported for JS;
  un-skipped, head passes both, so the policy entry is stale and needs a cross-sdk-tests change), 323 (blank application),
  400–420 and 422–425 (unimplemented switchbacks). No wrapper was modified or
  observations filtered. Versioned agent GET/PUT is separately tested in this repo.
- External type consumer against artifact and candidate: TS3.9/4.4/4.9 probes.
  Main fails TS3.9/4.4 parsing; main on TS4.9 rejects released Exposure and
  PublishParams literals and non-strict getAttribute usage. Restored candidate
  compiles the released non-strict consumer under TS3.9.
- Dist-tag selection: prereleases go to their own tag (`beta`, `rc`, else `next`), never `latest`; a stable release goes to `latest` only when it is newer than the current latest; an older major goes to `v<major>-lts`; an older same-major backport is refused so the owner chooses its tag.
- Actual npm 11.6.2 dry run proves `--tag v1` is rejected as a semver range;
  use `v1-lts` for a maintained v1 when npm latest becomes v2+. No publication.

Further exact-head independent evidence is posted per push in the PR, including
mutation measurements and verification limits. Release preparation alone does not
claim all historical malformed input is supported or all SDK lanes are implemented.
